## 6. Assumptions Made

1. **Package naming convention**: Used `@repo/` namespace (matching existing `@repo/ui`, `@repo/eslint-config`, `@repo/typescript-config`) for the db package. The original `@sec-design-swarm/database` naming was inconsistent with the rest of the monorepo.

2. **Prisma 7 adapter pattern**: Prisma 7.8.0 no longer supports `datasourceUrl` in the `PrismaClient` constructor or `url` in the schema's `datasource` block. The project uses `@prisma/adapter-pg` with the `PrismaPg` driver adapter instead, which is the recommended Prisma 7 approach.

3. **No Prisma models**: The schema has no models. Prisma generates a valid (empty) client, but `prisma db push` will not create any tables. Models will be added during feature development.

4. **Worker queue name**: Used `design-review` as the BullMQ queue name, reflecting the project's purpose. This can be renamed during feature development.

5. **Port defaults**: HTTP server defaults to port `3001` (to avoid conflict with Next.js default `3000`).

6. **shadcn/ui preset**: Used the `base-nova` default preset with CSS variables. Only the `Button` component was auto-generated by `shadcn init`.

7. **Next.js scaffold**: Kept the create-next-app scaffold's default page and layout. These are functional defaults and will be replaced during feature development.

## 7. Deviations from Prompt

| Deviation | Reasoning |
|-----------|-----------|
| Added `@prisma/adapter-pg` and `pg` to `packages/db` | Prisma 7 requires a driver adapter — the `datasourceUrl` constructor option and `url` in `datasource` block are removed. This is a necessary adaptation to the current Prisma version. |
| `prisma.config.ts` kept from original `packages/database` | The existing config was already correct and compatible with Prisma 7 |
| shadcn/ui generated one `Button` component | The `shadcn init --defaults` command auto-generates a Button. This is part of the standard init, not an added component. |
| Used `eslint-config-next` in web app (not `@repo/eslint-config/next-js`) | The `create-next-app` scaffold generates its own ESLint config using `eslint-config-next`. Keeping it avoids compatibility issues with Next.js 16's ESLint integration. |

## 8. Remaining Setup Tasks

Before beginning feature development:

1. **Create `.env` from `.env.example`**:
   ```bash
   cp .env.example .env
   ```

2. **Start infrastructure**:
   ```bash
   pnpm docker:up
   ```

3. **Design the Prisma schema** in `packages/db/prisma/schema.prisma` — add your domain models.

4. **Push schema to database**:
   ```bash
   pnpm db:push
   ```

5. **Regenerate Prisma client** after schema changes:
   ```bash
   pnpm db:generate
   ```

6. **Replace default web app content** — the Next.js scaffold's default page (`apps/web/src/app/page.tsx`) should be replaced with actual application UI.

7. **Clean up default Next.js assets** — remove placeholder SVGs from `apps/web/public/` when actual assets are available.

8. **Configure CI/CD** — add GitHub Actions or similar for build, lint, and type-check pipelines.

9. **Add `.env` handling** — consider a tool like `dotenv-cli` or ensure each app loads env vars appropriately for its runtime context.
